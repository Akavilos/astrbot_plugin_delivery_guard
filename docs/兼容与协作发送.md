# 兼容范围与协作发送

本插件使用 AstrBot 的公开事件、框架日志和插件数据目录，不替换 Context、事件类、供应商或协议端的方法。

## 框架默认流程

已知不可送达时，`on_llm_request` 可以记录当前来信并停止相关请求。非流式消息经过 `on_decorating_result` 时，再检查一次已知状态；被拦的文字加入自己的待发队列。未被拦的内容由框架按原流程发送。

框架的发送后钩子不是可靠的成功回执。流式消息、直接 `event.send()` 和其他插件的主动发送也未必经过相同事件钩子。因此本插件无法自动观察所有主回复的发送异常；需要完整跟踪的插件应主动采用协作接口。

## 协作接口

持有投递哨兵插件实例 `guard` 时，调用：

```python
from astrbot.api.event import MessageChain
from astrbot.api.message_components import Plain

await guard.send_guarded(umo, MessageChain(chain=[Plain("要发送的文字")]))
```

`umo` 是框架提供的 `event.unified_msg_origin`。插件实例由接入方通过自己的依赖组织持有，不能通过改写框架发送方法代替接入。

已知不可达时，接口保存文字并抛出 `DeliveryBlocked`；发送异常时记录故障、暂存文字并重新抛出原异常。Context 返回 False 表示未找到目标平台，同样作为发送失败处理。成功返回表示接口完成发送，不代表用户已阅读或平台提供端到端送达证明。

总开关关闭或会话不在保护范围时，接口按原 Context 发送，不增加哨兵记录。`track_outcome` 控制正常协作发送的结果记录；补发队列始终根据实际返回结果处理，不会因关闭该选项丢弃失败内容。

## 数据与恢复

`guard.db` 独立保存在框架的插件数据目录，原有表结构不变。文字队列保留失败条目，按有效期、批量及间隔补发；群查询需按配置连续确认恢复，真实试发成功则确认当前发送通路。时间到期本身不代表恢复。

图片、语音、视频等媒体不自动补发。恢复背景注明原来信的发言人和时间，作为本轮临时内容提供给模型，不覆盖角色基础提示词。

接口参考：[AstrBot 消息事件](https://docs.astrbot.app/dev/star/guides/listen-message-event.html)、[公开 Context 实现](https://github.com/AstrBotDevs/AstrBot/blob/master/astrbot/core/star/context.py)。
