# 投递哨兵 0.1.3 · AstrBot 兼容更新

本次按插件市场的日志、临时上下文和框架兼容要求调整接入方式。

- 日志仅从 `astrbot.api` 导入，不使用内置 logging 或回退导入。
- 恢复背景使用 `req.extra_user_content_parts` 与 `TextPart.mark_as_temp()`，不改变系统提示、框架历史或永久聊天记录。
- 移除 Context 和 QQ 发送类的猴子补丁。正常框架发送保留原来的分段及适配器行为，新增明确的 `send_guarded` 协作接口。
- 通过公开事件获取机器人身份，通过 `get_platform_inst`、`get_client` 和 OneBot 异步查询检查权限，不读取私有连接字段。
- 不将框架发送后通知直接判定为送达成功。平台未找到返回 False、实际发送异常、未确认的恢复试探，都不会把待发内容错误标记为已送达。
- 不在查询未知时提前修改恢复状态。每次试探一条，恢复后继续处理剩余批次，发送失败保留原队列，避免重复入队或重复计算成功次数。

能力范围见[兼容与协作发送](兼容与协作发送.md)。群禁言、缺席来信、文字暂存与补发、诊断、管理指令及原配置分组保留。数据库结构不变，升级不清空旧记录。

已在 AstrBot 4.28.1 隔离容器内验收公开接口与核心行为。协议端和发送结果为模拟对象，没有连接真实 QQ 或模型；审核结果以 AstrBot 市场为准。
