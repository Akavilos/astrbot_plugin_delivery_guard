# 投递哨兵 · Delivery Guard

投递哨兵帮助 AstrBot 识别群禁言和消息发送故障。会话被判定不可送达时，拦截相关模型回复流程，记录错过的来信与待补发内容；恢复后按有效期、批量和间隔安排补发。

本版本：**0.1.1**。主要面向 **OneBot / aiocqhttp** 的QQ机器人环境。

## 主要功能

- 检查群内机器人禁言与全员禁言，跟踪真实发送结果。
- 对受保护的异常会话暂停不必要的回复生成。
- 独立保存缺席期来信与待补发内容，恢复后提供简短背景。
- 按有效期、每批条数和发送间隔补发，连续试探失败时降低重试频率。
- 用指令查看、探测、补发或手动标记当前会话。

哨兵可独立使用，也可与光谱配合。它管理“消息能否送达”，光谱的异常冻结管理“生活与任务是否推进”；两者不是同一个开关。哨兵不直接修改其他插件的数据库，恢复背景会追加到当前模型请求中。

## 安装与开始使用

1. 使用 AstrBot **4.24.0 或更新版本**，确认QQ适配器能正常发送消息。
2. 将 `astrbot_plugin_delivery_guard` 放入 `data/plugins` 并加载。
3. 插件配置 → 开始使用，打开“启用投递哨兵”，选择保护范围。总开关默认关闭。
4. 保留默认检测与恢复设置，保存并重载。
5. 发送 `/哨兵` 看状态，群聊中可用 `/哨兵 probe` 检查探测结果。

群探测依赖协议端返回禁言信息。私聊不能仅靠查询确定拒收，需要实际发送结果，因此首次识别会有延迟。补发只能重新发送内容，不能补回原来的发送时间。

## 升级与数据

分组配置保留旧值。缺席来信和待补发内容保存在独立数据目录的 `guard.db`，升级时保留数据库和配置。补发数量超出本批上限的内容仍留队列，是否过期由有效期控制。


## 全新安装与个人数据

发布源码不包含聊天记录、个人实例的数据库、私人配置或部署凭据。全新数据目录从空的业务数据开始；升级已有实例时保留原数据。
