# 投递哨兵 · Delivery Guard

投递哨兵帮助 AstrBot 检查群禁言、保存无法回应期间的来信，并在恢复后按有效期、批量和间隔补发积压文字。它通过公开事件接入，不修改框架或其他插件的发送方法。

当前版本：**0.1.3 · AstrBot 兼容版**。主要面向 **OneBot / aiocqhttp** 的 QQ 机器人，要求 AstrBot 4.24.0 或更新版本。

## 主要功能

- 查询机器人禁言与全员禁言，暂停已知不可送达会话的模型回复。
- 保存缺席来信，并将恢复背景追加到本轮临时内容。
- 暂存被公开发送前钩子拦下的文字，按有效期、批量与间隔补发。
- 通过明确的协作发送接口记录真实成功或失败，试发失败保留队列。
- 提供状态、诊断、探测、补发、清理来信和手动状态指令。

哨兵可独立使用，也可与光谱配合。它管理消息能否发送；光谱的异常冻结管理生活与任务是否推进，两者分别设置。哨兵不操作光谱或框架的聊天数据库。

## 安装与开始使用

1. 在 AstrBot 中通过插件市场或仓库地址安装本插件，确认 QQ 适配器能正常连接。
2. 打开插件配置的“开始使用”，开启哨兵并选择保护范围；总开关默认关闭。
3. 保留默认群检查与恢复参数，按需要设置补发有效期、每批条数和发送间隔。
4. 保存并重载，使用 `/哨兵` 查看状态，群聊中使用 `/哨兵 probe` 检查查询结果。

全新安装不包含聊天记录、联系人、角色人设或密钥。数据独立保存在框架提供的插件数据目录内的 `guard.db`；升级保留原数据库和配置。

## 兼容范围

未被拦的回复继续使用 AstrBot 原来的发送、分段与适配器流程。恢复背景仅使用 `extra_user_content_parts` 与临时标记，不清空历史、不改写系统提示或永久聊天记录。

框架发送后钩子不保证消息发送成功；部分流式路径也不经过发送前后钩子。本插件不会把这些通知当成真实送达回执。其他插件的主动发送、绕过公开钩子的直接发送，以及已开始输出的流式消息，不受全局接管。

私聊没有通用的拒收查询接口，需要协作发送结果或手动状态标记。需要完整失败跟踪和暂存的插件应显式调用 `send_guarded`，见[兼容与协作发送](docs/兼容与协作发送.md)。

待发队列只保存文字，不自动补发图片、语音、视频等媒体。群查询按配置连续确认恢复；实际试发成功可以确认当前发送通路。仅有时间到期或查询失败，不会把会话直接标记为恢复。发送成功不代表对方已阅读。
